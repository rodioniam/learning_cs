# Обобщения - Generics
Это способ писать код так, чтобы он мог работать с различными типами данных, сохранив при этом строгую типизацию `C#`. Одним из плюсов генериков является возможность избегать процессов упаковки и распаковки. Так же обобщения позволяют легче повторно использовать код - при правильном использовании можно написать код так, что он будет работать сразу с несколькими типами данных и не придется писать отдельную функцию под каждый тип данных.

Если метод принимает один generic тип, значит он не может в качестве аргументов принимать два разных типа - они должны быть одного типа, который будет воспринят как generic тип для метода.

Под капотом однако никакой магии не происходит - каждый раз при компиляции кода генерируется метод, который соответствует передаваемым в него типам аргументов. 

## Производительность обобщений, List и ArrayList
Если сравнивать производительность методов, которые используют `generic` типы и `object` типы, то `generic` методы будут сильно быстрее. Это происходит потому что происходит упаковка значимых типов в ссылочные (из структур в класс `object`). `generic` же работает по другому - во время компиляции кода создается метод с теми типами данных параметров, которые требуются.

`List` - это массивы реализованные через `generic`, а `ArrayList` - через `object`, отсюда вытекает и такая же разница в производительности. Массив из `object` элементов будет хранить ссылки на объекты, которые могут быть где угодно в памяти (управляемой куче). Из-за этого и сборщик мусора будет работать дольше, так как ему придется удалять не только саму коллекцию, но и все элементы, на которые она ссылается. 

Для обобщений (`generic`) генерируется свой собственный код с нужным типом данных, поэтому массив будет хранить не ссылки, а реальные данные. 

Поэтому `ArrayList` нет особого смысла использовать, тем более учитывая то, что из массива `List` можно сделать массив `object` просто указав его как тип при объявлении массива.
