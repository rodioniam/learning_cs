## Стек (stack) и куча (heap)
Эти оба понятия относятся к оперативной памяти, но используется она в них по разному, для разных целей и имеет разный объем. Для стека используется малый объем, а для кучи большой. 

`Stack` - это небольшой объем памяти, который выделяется для каждого потока (default = 1mb). На данном этапе это каждый отдельный файл со скриптом, который я писал тут. Позволяет очень быстро размещать и очищать данные. Работает по принципу `last in - first out` - последняя задача или переменная, которая попала в стек, будет извлечина из него первой.

`Heap` - это нечто вроде склада в оперативной памяти. Объем может быть разным и зависит от аппаратной платформы, на которой запускается программа. Например, для 32 разрядных систем это около 1.5гб, а для 64 разрядных - до 8тб. Накладно выделять место под данные и более проблематично их очищать. Однако в C# есть `Garbage Collector` как и в Python. 

| Что нужно знать? | Value Types (значимые типы) | Reference Types (ссылочные типы) |
| ---------------- | --------------------------- | -------------------------------- |
| Где размещаются объекты?| Stack | Heap |
| Как отличить? | struct, enum (неявно унаследованы от System.ValueType) | class (может быть производным от любого другого типа, если только этот тип не назначен) |
| Когда прекращают существование? | Когда покидает контекст, в котором были определены | Когда объект подвергается сборке мусора |
| Поведение при передачи параметров и копировании | Переменные передаются по значению (копируются реальные данные) | Копируется ссылка, оригинал и копия ссылаются на один и тот же объект в `heap` = одни и те же данные|


## Преобразование и приведение типов
Тут похожая видимо ситуация с Python и некоторые типы данных `C#` конвертирует под капотом когда это нужно.

Некоторые типы поддерживают неявное преобразование, а некоторые нет. Зависит это по большей части от максимально и минимально допустимых значениях, которые могут хранить типы. Например, `double` может хранить значения, сильно больше чем может хранить `float`, поэтому хоть и оба типа это значения с плавающей точкой, неявное преобразование из `double` во `float` невозможно.

## Сужающее и расширяющее преобразование.
Это по сути то же самое, только немного в другой классификации. Там где происходит явное приведение типов происходит сужающее преобразование. Когда происходит неявное приведение типов - расширяющее преобразование.

### Проблема переполнения данных.
При достижении максимально допустимого значения в типе данных есть возможность его переполнить через верхнюю или через нижнюю границу. При переполнении через верхнюю - превышение максимально допустимого значения - переменная этого типа получит минимально допустимое значение. В ситуации наоборот - превышение минимально допустимого значения (переполнение через нижнюю границу), переменная получит максимально допустимое значение. На лицо явная опасность - в первом случае из положительного получаем максимально возможное отрицательное значение, а во втором из отрицательного значения получаем максимально положительное значение.

Есть способ с этим бороться - использование ключевых слов `checked` и `unchecked` или включением проверки глобально для проекта. Для включения глобально нужно в файл с расширением `csproj` добавить такую строку - `<CheckForOverflowUnderflow>true</CheckForOverflowUnderflow>`. После включения любой случай overflow будет кидать ошибку и останавливать выполнение программы. 

Не всегда удобно включать глобальную проверку и она к тому же замедляет выполнение программы, поэтому можно использовать ключевые слова `checked` и `unchecked` в местах потенциального возникновения переполнения. Если первое выполняет проверку и кидает ошибку при возникновении overflow, то второе используется при включенной глобальной проверке для мест, где нам не нужно бросать ошибку при появлении overflow.

Все выше сказанное относится к `int` и `byte`, для `float`, `double` переполнения нет, они могут принимать значения бесконечности или NaN. Для их проверки используются соответствующие методы. Для типа `decimal` всегда при overflow будет ошибка.


## Nullable
Изначально использовалась для того чтобы значимые типы могли хранить значение null.

## Ключевое слово Var
Это неявно типизированные локальные переменные. Это не тип данных, а просто способ не указывать конкретный тип данных при объявлении переменной. Методы не могут принимать параметр со значением `var`, не могут возвращать `var`.
