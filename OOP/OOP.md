# ООП в C#
## Модификаторы доступа
### Public и Private
Основные компоненты инкапсуляции. Из названий понятно что каждый делает. Действует только за пределами рамок области видимости в которых были объявлены. Игнорируются другими методами класса, если те публичны. Это значит, что метод класса с модификатором `public` может выводить `private` поля или использовать внутри себя и выводить результат `private` методов этого же класса. По умолчанию всегда используется `private` модификатор, но хорошим тоном является явное указание приватности.

# Инкапсуляция
Главным образом реализуется через модификаторы доступа. Все методы класса не доступны извне, доступны только те, что выполняют главную и основную функцию метода или класса. Защищают логику и переменные внутри класса от внешнего мира.

## Конструктор класса
Это метод класса, который вызывается при создании объекта такого класса. Скорее всего это очень похоже на Python `self.__init__`. У каждого класса он есть по умолчанию, но можно создать свой вариант. В конструкторы можно добавлять параметры.

Возможна перегрузка конструкторов класса. Тут так же как с методами. Внутри класса можно объявить несколько конструкторов и создавать класс с разными параметрами.


## Static

### Static поля класса
Поля класса с модификатором `static` будут доступны для всех объектов данного класса. И для работы с данной переменной нет необходимости создавать объект класса, можно обращаться через сам класс. Статическим методам так же можно добавлять свойства


### Static методы класса
Принцип работы ключевого слова `static` с методами схож с тем, как оно работает и с полями класса - метод можно использовать не создавая экземпляр класса. При использовании статичного метода внутри своего класса есть некоторые особенности: статичные методы могут работать только со статичными переменными внутри своего класса. В случае использования `static` для методов класса теряется возможность использовать полиморфизм в классическом понимании `OOP`.

#### `Static` свойства
Такие свойства это два метода - `get` и `set` - так же могут иметь параметр `static` - могут быть доступны только на уровне класса.

### Static конструктор класса
Если обычный конструктор класса создает экземпляр класса с любыми методами и переменными, то `static` конструктор класса может делать это только для статических членов класса. В классе может быть только один статический конструктор, поэтому перегрузка статического конструктора невозможна. Еще статический конструктор не может принимать параметры. Статический конструктор вызывается только при любом первом взаимодействии с классом, далее он вызываться не будет. 

### Static классы
Добавление параметра `static` для класса запрещает создание экземпляров данного класса. Статический класс не может содержать в себе не статические методы и переменные. 

Такие классы не поддерживают полиморфизм, наследование и dependency injection. Статические классы часто используют как утилитарные\вспомогательные классы.


# Extention Methods
Если мне нужно дополнить существующий класс новым методом мне не обязательно переписывать сам класс. Методы расширения должны находиться в статическом классе и сами по себе тоже должны быть статическими. 

Поддерживают передачу параметров.

### Изоляция методов расширения
Должны находиться в одном `namespace`. Если же должны выйти за рамки одного `namespace`, то можно импортировать через `using наше namespace`.

# `Const` vs `Readonly`
Модификатор `const` запрещает изменять данные переменной после того как они туда попали, поэтому при объявлении константной переменной в нее нужно сразу поместить какие то данные. Обычно константы пишут ВОТ_ТАК. Так же данные поля неявно статические. Из-за необходимости сразу присваивать значение константам их использование не всегда удобно, так как иногда бывает так, что данные, которые нельзя изменять могут получиться только в результате работы программы. Для таких случаев используется модификатор `readonly` - при объявлении переменных с таким модификатором нет необходимости сразу присваивать им данные. `readonly` объекты не являются `static`, поэтому для взаимодействия с ними нужно создавать объекты класса. Изменить `readonly` поля можно только в конструкторе класса.

Поля `readonly` могут быть статическими, но тогда нужно обязательно объявлять статические конструкторы.


# Наследование
Ну вроде ничего сложного пока, наследуется через :

## Наследование конструкторов класса, ключевое слово `base`
Если у родительского класса реализован конструктор класса с параметрами, то необходимо реализовать такой же конструктор у нового класса или использовать конструктор родительского класса через ключевое слово `base`. Это ключевое слово указывает, что нужно взять базовые параметры из родительского класса.

Однако `base` не ограничивается только конструкторами класса - он в принципе позволяет указывать, что какой то элемент нового класса должен быть взят из родительского класса.

## Приведение типов
Приведение типов при наследовании можно осуществить при помощи оператора `as` или `is`. Обычное приведение типов (через указание в скобочках типа) при несоответствии приводимого объекта бросит ошибку и остановит код. Эти же операторы умеют выполнять проверку и не останавливать выполнение кода. `as` будет помещять в объект `null` если не подходящий тип, а `is` может прям на ходу проверки присваивать конвертируемый объект в новую переменную. 

Наверное такое может пригодиться когда мой какой то кастомный класс может возвращать несколько типов данных, а новый класс может принимать только какой то определенный.

## Модификатор `protected`.
Модификатор доступа `protected` имеет смысл только при использовании наследования.
Внутри класса объекты с модификатором `protected` доступны без каких либо ограничений. Вне класса доступа к полям с таким модификатором нет.

У зависимого класса не будет доступа к приватным полям родительского класса, а вот доступ к публичным и защищенным полям будет.

Это позволяет инкапсулировать какую то логику внутри родительского класса, чтобы зависимые классы ее не могли менять


# Полиморфизм
Инструменты для реализации полиморфизма в `C#` - `virtual` и `override`. эти ключевые слова позволяют переопределить работу метода в зависимом классе. У переопределяемых методов должны быть такие же модификаторы, название и набор параметров как и у родительского класса, где был объявлен этот метод впервые. 

В виртуальных методах очень часто используется модификатор `protected` - в отличие от приватного модификатора (который полностью убирает доступ к полю вне класса), данный модификатор оставляет доступ к полю в зависимом классе, оставляя его при этом недоступным снаружи класса.

## Абстрактные классы, методы и свойства
Абстрактный класс - это некая идея, описание или частичная реализация класса. Все что написано внутри абстрактного класса может быть использовано только внутри наследников этого класса, создать объект непосредственно самого абстрактного класса нельзя.

Если в абстракном классе есть абстрактный метод, то все наследники этого класса обязаны реализовать этот метод.


# Интерфейсы
Можно сравнить с абстрактными классами, у которого только абстрактные методы (без реализации). С помощью интерфейса определяется поведение, которое в последствии будет реализовано в каком то конкретном классе. Интерфейсы позволяют множественное наследование, они могут наследоваться между собой, один интерфейс может унаследовать несколько разных, один класс может унаследовать несколько интерфейсов. Правильно говорить "класс реализует интерфейс".

В интерфейсах не может быть конструктора, они не могут содержать поля класса. По умолчанию все поля интерфейсов имеют модификатор `public`.

Обычно в реальных проектах для интерфейсов создаются отдельные файлы, как и для классов - каждая отдельная сущность находится в отдельном файле.

## Наследование интерфейсов
Классический синтаксис наследования не применим к интерфейсам. Наследовать интерфейсы могут только интерфейсы, правила при наследовании абсолютно такие же как и при наследовании классов - должны реализовывать методы родительского интерфейса. Интерфейсы в отличие от классов поддерживают множественное наследование. 

Это позволяет упростить добавление нового функционала уже в существующие классы, которые реализуют какой либо интерфейс. Из-за того что интерфейс наследник будет содержать методы изначального интерфейса, частичная реализация интерфейса наследника уже будет осуществлена в классе.
